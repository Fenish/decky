# USB first, Wi-Fi only without a cable, no manual switch

**Context:** unplugging USB from a deck that stayed powered (by a monitor port)
left the dashboard up, because the app quietly reconnected over Wi-Fi inside a
single status check. The user first chose to keep that fallback and make it
visible, then asked for no switching at all, then settled on this.

**Choice:** the app connects over USB whenever a cable answers and over Wi-Fi
only otherwise. While on Wi-Fi, a USB port that answers `ID` with the same
serial takes over again; ports that are not this deck are re-checked at most
every 30 s. There is no "Use Wi-Fi" or "Use USB" control. The title bar names
the connection in use, and a lost USB link that continues over Wi-Fi is
announced.

**Why:** the user's words: "USB wired first, fallback Wi-Fi", and "I don't want
to switch connection modes".

**Rejected:**

- _A preferred-transport setting._ The previous design; the user did not want
  modes.
- _Strict single transport._ Built for one message, then reversed: a deck on a
  power-only monitor port would never connect.

See [[connection-priority]].
